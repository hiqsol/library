# Disposable Software: The Trend 90% of People Are Getting Wrong — Summary

**Date:** 2026-01-20 15:01

The cost of software has collapsed toward zero. 65% of the last YC batch
shipped 95%+ AI-generated codebases. Cursor went from $2.6B to $29B in
a year. Lovable hit $100M ARR in 8 months. 75% of Replit users never
write code.

Cursor built a web browser with AI in one week (3M lines of Rust).
Chrome took 2+ years with elite engineers for its first beta. This is
not a small change — it is an inversion.

Disposable software is actually two phenomena: (1) throwaway personal
software (dashboards, vacation apps) — unambiguously good; (2) disposable
features within enterprise products — ship constantly, only harden what
sticks.

Disposable software kills planning rituals: product management, user
research, roadmap planning, design documents. These existed because
building the wrong thing was expensive. Now you just ship and see.

Critical distinction: developers tolerate instability; CIOs do not.
Enterprise customers buy reliability and peace of mind. Even Cursor's
own developer users complain about instability.

The "vibe-code your own Salesforce" argument has a fatal flaw: attention,
not software cost, is the constraint. Diverting builders from core
business to vibe-code internal tools has incalculable opportunity cost.
AI-generated code introduces security vulnerabilities in ~50% of tasks.

The right enterprise AI strategy is proactively reliable: (1) prove
reliability first — uptime, security certs, responsive support; (2) then
extend into proactive AI that creates value customers didn't know they
were missing. Skip step one and you terrify customers.

Proactive AI differs fundamentally from chatbots. It analyzes without
being asked, surfaces insights, takes appropriate action autonomously.

Simpler interfaces absorb constant change better — Claude Code's
terminal ships 1000+ commits without user friction, while Cursor's
rich GUI generates instability complaints.

Four discourse errors: treating all software as equivalent, ignoring
opportunity cost, underestimating the reliability market, treating the
5% edge case (developers) as the 95% general case.
